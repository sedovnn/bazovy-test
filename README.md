# Базовый тест «Карта стратегических навыков»

Пятнадцать минут: шесть ситуаций с расстановкой ответов и записка на 150–250 слов.
Участник заходит по коду сессии или по QR, получает карту из пяти навыков.
Ведущий видит сводку по группе — без имён и без текстов ответов.

Отдельный продукт: свой репозиторий, свой проект Apps Script, свой ключ API.
С Искрой и с платформой не пересекается ничем, кроме визуальных токенов, которые
скопированы в `css/app.css` (не импортированы).

| | |
|---|---|
| Участник | https://sedovnn.github.io/bazovy-test/ |
| Ведущий | https://sedovnn.github.io/bazovy-test/host.html |
| Ссылка в QR | `https://sedovnn.github.io/bazovy-test/index.html?s=КОД` |
| Репозиторий | https://github.com/sedovnn/bazovy-test |

Сайт обновляется сам через минуту после `git push` в `main`.

## Что где лежит

```
index.html            участник: вход → блок А → блок Б → ожидание → карта
host.html             ведущий: создать сессию, код и QR, живой агрегат
css/app.css           единственный CSS: токены + компоненты
js/data.js            тексты теста          ← собирается из spec/
js/keys.js            ключ расстановки      ← НЕ В РЕПОЗИТОРИИ, см. ниже
js/scoring.js         подсчёт блока А и сборка карты
js/qr.js              QR-код, свой, без внешних сервисов
js/api.js             вызов бэкенда + моковый бэкенд для локальной работы
js/test.js            экраны участника
js/host.js            экран ведущего
apps-script/          бэкенд, см. ниже
spec/                 СПЕЦИФИКАЦИЯ — источник истины по содержанию
tools/                генератор и проверки
```

**Источник истины — `spec/`.** Там два файла: базовый тест (задания, варианты,
ключи, подсчёт) и промпт судьи. Тексты нигде не переписываются руками.

### Чего в этом репозитории нет

Репозиторий публичный, а GitHub Pages отдаёт из него всё подряд. Поэтому четыре
позиции сюда не коммитятся — иначе участник, заглянувший в репозиторий, получил
бы ответы:

```
spec/                        задания, ключи, промпт судьи
js/keys.js                   ключ расстановки
apps-script/keys.gs          он же для бэкенда
apps-script/judge_prompt.gs  промпт судьи целиком
```

Они лежат локально и в проекте Apps Script. Три последних восстанавливаются из
`spec/` одной командой:

```bash
python3 tools/собрать_данные.py
```

**`spec/` не восстанавливается из этого репозитория — это отдельный источник
истины.** Он лежит в приватном `sedovnn/bazovy-test-spec`: та же папка
`spec/` внутри рабочей копии, но со своим git и своим адресом. Здесь она в
`.gitignore`, поэтому в публичный репозиторий не попадает.

```bash
git clone https://github.com/sedovnn/bazovy-test-spec.git spec
python3 tools/собрать_данные.py
```

По образцу Искры: `imperfect-iskra-platform` публичный, `imperfect-iskra-backup`
приватный.

Тексты ситуаций (`js/data.js`) в репозитории есть — их браузер участника грузит
в любом случае, публичность репозитория тут ничего не добавляет. Ключей в них нет.

## Как поднять локально

```bash
python3 -m http.server 8777
```

Открыть `http://localhost:8777/host.html`, создать сессию, перейти по ссылке или
отсканировать QR.

Если репозиторий только что склонирован, моковый режим не заработает, пока нет
`js/keys.js`: положите `spec/` на место и прогоните генератор. На живом сайте это
не нужно — там считает Apps Script.

Пока в `js/api.js` пустой `API_URL`, работает моковый бэкенд:
данные лежат в `localStorage` браузера, судья имитируется. Этого хватает, чтобы
прощёлкать весь путь.

Посмотреть, как выглядит карта, когда судья не ответил: добавить к адресу
`?mockfail=1`.

## Apps Script — десять шагов

1. `script.google.com` → **Новый проект**, назвать «Базовый тест».
2. Загрузить в проект файлы из `apps-script/`: `Code.gs`, `judge.gs`, `scoring.gs`,
   `config.gs`, `keys.gs`, `judge_prompt.gs` (порядок не важен).
3. Значок шестерёнки → **Настройки проекта** → включить «Показывать файл манифеста»,
   открыть `appsscript.json` и вставить содержимое одноимённого файла из `apps-script/`.
4. Там же, **Свойства скрипта** → добавить `ANTHROPIC_API_KEY` = ключ Anthropic.
5. По желанию добавить `MODEL` (по умолчанию `claude-sonnet-5` — как у судьи Искры).
6. Выбрать функцию `проверитьСудью`, нажать **Выполнить**, выдать разрешения,
   убедиться в логах, что пришёл JSON с четырьмя уровнями.
7. **Развернуть** → **Новое развёртывание** → тип **Веб-приложение**.
8. «Запуск от имени» — **от моего имени**; «Кто имеет доступ» — **Все**.
9. Скопировать URL веб-приложения (заканчивается на `/exec`).
10. Вставить его в `js/api.js`, строка `var API_URL = '';`, затем `git push` — Pages
    подхватит через минуту.

До этого шага сайт уже открывается, но на любое действие честно отвечает
«бэкенд не настроен» — это ожидаемое состояние, а не поломка.

Таблица с данными создаётся сама при первом обращении, её идентификатор
скрипт запишет в свойство `SHEET_ID`. Ключ API остаётся на стороне Apps Script и
в браузер не передаётся никогда.

**Правки в коде после публикации** подхватываются только новым развёртыванием:
**Развернуть → Управление развёртываниями → карандаш → Версия: новая**.

## Как добавить этап «после модуля»

Тест один и тот же, меняется только метка этапа. Ведущий создаёт новую сессию и
выбирает этап в выпадающем списке: «До программы» (`baseline`), «После модуля»
(`module`), «Финал» (`final`). Этап пишется в обе таблицы, сводка считается по
коду сессии, поэтому сравнение делается между сессиями, а не внутри одной.

Добавить свой этап — в `tools/собрать_данные.py`, список `stages` в конце
функции `main`, затем прогнать генератор. Ничего больше менять не нужно.

## Когда пришла новая версия спеки

```bash
# положить новый md в spec/, прежний убрать — файл должен быть один
python3 tools/собрать_данные.py
python3 tools/сверить_тексты.py
```

Генератор перепишет `js/data.js`, `js/keys.js`, `apps-script/keys.gs`,
`apps-script/config.gs`, `apps-script/judge_prompt.gs` и `apps-script/scoring.gs`.
Эти файлы руками не правят — следующий прогон затрёт.

Если разметка спеки изменится, генератор упадёт с понятной ошибкой, а не соберёт
молча половину. Чинить в этом случае надо парсер в `tools/собрать_данные.py`,
а не подкладывать данные вручную.

После генерации файлы `config.gs`, `keys.gs`, `judge_prompt.gs`, `scoring.gs`
нужно заново загрузить в проект Apps Script и сделать новое развёртывание.

## Проверки

```bash
node tools/прогон_бэкенда.js      # бэкенд на заглушках: подсчёт, запись, падение судьи, повтор
python3 tools/сверить_тексты.py   # тексты в data.js дословно совпадают со спекой

```

Для проверки QR нужны сторонние пакеты, в проекте они не используются:

```bash
pip3 install --target /tmp/qrlibs opencv-python-headless numpy segno
PYTHONPATH=/tmp/qrlibs python3 tools/сверить_qr.py
```

## Что решено за пределами спеки

Спека в двух местах не дописывает границы — прочитано так, правится в одном месте
(`js/scoring.js`, оно же `apps-script/scoring.gs`):

- **«Перестановка соседей»** — ровно один обмен двух соседних позиций, остальное на
  местах. Проверяется раньше правила «L5/L4 первым», иначе ответ с переставленными
  первыми двумя получил бы 2 вместо 3.
- **«L5/L4 на 2–3-м месте»** — L5 или L4 стоит вторым или третьим, при том что
  первым не стоит ни один из них. Оба на 4–5-м местах — 0.
- **«Различаю, но не делаю»** — расстановка в зоне «выбирает», а уровень той же
  способности в записке L1 или L2. Пороги вынесены в константы `GAP_ZONE`
  и `GAP_MAX_LEVEL`.

Ещё три решения:

- **Варианты в спеке v1.0 идут без букв**, а ключ записан буквами. Буквы раздаются
  по порядку следования: первый «-» = A, пятый = E. В v0.9 буквы стояли явно и шли
  ровно в этом порядке. Проверить глазами на новой версии:
  `node -e "const T=require('./js/data.js'),K=require('./js/keys.js');for(const s of T.blockA){console.log(s.factor);for(const o of s.options)console.log(' ',o.id,'= L'+K[s.id][o.id],o.text.slice(0,60))}"`
- **Порог отправки записки — 100 слов**, это из ТЗ продукта. Спека просит 150–250,
  и именно эти числа показаны участнику как ориентир.
- **Коды способностей участнику не показываются** — в шапке ситуации стоит
  «Ситуация N из 6». Так требует v1.0.

## Стиль

Токены скопированы из платформы «Искра» (`imp.v3/css/styles.css`, блок `:root`)
и её `DESIGN.md`. Скопированы, а не импортированы: проекты живут независимо.

Вермилион `#ff4800` — на входе и на карте результатов. Внутри теста вся семья
акцента голубая (`body.p-test`): в Искре это решение владельца от 07.08 —
внутри ассессмента вермилиона нет.

**Тёмной темы нет**, и это не упущение: её нет и в Искре. `DESIGN.md` прямо
запрещает тёмный фон, тёмное там ровно одно — плашка футера. Делать свою
означало бы сочинить палитру, которой в системе не существует.

Теней нет нигде: глубина — hairline-линии и бледные тинт-заливки. Радиус один
на весь проект — 8px.

## Расходы

Промпт судьи подаётся целиком, как требует спека, — это около 60 тысяч знаков
на каждый вызов. Он статичный, поэтому помечен `cache_control` и при потоке
участников подряд считается по цене кэша. Один вызов на участника, плюс вызов
на каждый `rejudge`.
