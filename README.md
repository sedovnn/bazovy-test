# Базовый тест «Карта стратегических навыков»

Около пятнадцати минут: одна новость о крупной международной компании, 6 веток комментариев
под ней и 3 своих коротких комментария. Участник заходит по коду сессии или по QR,
получает карту из пяти навыков. Ведущий видит сводку по группе без имён и может
вывести на экран комментарии группы — без авторов.

Отдельный продукт: свой репозиторий, свой проект Apps Script, свой ключ API.
С Искрой и с платформой не пересекается ничем, кроме визуальных токенов, которые
скопированы в `css/app.css` (не импортированы).

| | |
|---|---|
| Участник | https://sedovnn.github.io/bazovy-test/ |
| Ведущий | https://sedovnn.github.io/bazovy-test/host.html |
| Ссылка в QR | `https://sedovnn.github.io/bazovy-test/index.html?s=КОД` |
| Репозиторий | https://github.com/sedovnn/bazovy-test |

Сайт обновляется сам через минуту после `git push` в `main`.

## Как устроен тест

Кейс — одна новость о реальной компании, как пост в канале: заголовок (компания и дата), событие, фон абзацами. Под ней 6 веток комментариев: каждую открывает реплика из ветки («Как это вообще сходится?»), под ней 4 комментария — без букв и без нумерации, в случайном порядке. Человек расставляет их от того, который написал бы сам, до того, с которым согласен меньше всего. Новость на первой ветке открыта, дальше свёрнута в строку и раскрывается по нажатию.

Ветки идут от прошлого к будущему и в каждом кейсе меряют одно и то же: 1 — широта охвата, 2 — глубина связей, 3 — идеи из других областей, 4 — основание выбора, 5 — ресурсы и ограничения, 6 — образы будущего.

По ходу человек трижды пишет свой комментарий, от 20 слов: после расстановки в ветке 4 — план к цели из вопроса; в ветке 5 — до расстановки, чтобы готовые ходы не подсказали ответ; после расстановки в ветке 6 — куда повёл бы компанию.

Расстановка даёт 0–3 балла за ветку. Свои комментарии читает судья по методологии v8 и профилю мини-формата: по четырём способностям уровень 1–5 или «ручная проверка», если спорная граница решает уровень. На карте пять навыков, одна общая шкала и компактный отчёт — по 1–2 строки на способность («В тесте», «В ответе», при ручной проверке — «Уточняется»), свёрнутое «О чём этот навык», в конце приписка и «Как тренировать» — тексты методолога.

**Кейсов шесть, одной структуры:** Intel, Nike, Starbucks, bp, Stellantis, Novo. Ведущий выбирает кейс на любом этапе; одному человеку один кейс дважды не даётся — так требуют правила.

## Что где лежит

```
index.html            участник: вход → 6 новостей → ожидание → карта
host.html             ведущий: создать сессию, код и QR, живой агрегат, «до/после»
css/app.css           единственный CSS: токены + компоненты
data/case_*.json      тексты кейсов, по файлу на кейс  ← собирается из spec/
js/config.js          общая часть: навыки, способности, этапы, список тестов
js/keys.js            ключ расстановки      ← НЕ В РЕПОЗИТОРИИ, см. ниже
js/scoring.js         подсчёт расстановок и сборка карты
js/qr.js              QR-код, свой, без внешних сервисов
js/api.js             вызов бэкенда + моковый бэкенд для локальной работы
js/test.js            экраны участника
js/host.js            экран ведущего
apps-script/          бэкенд, см. ниже
spec/                 СПЕЦИФИКАЦИЯ — источник истины по содержанию
tools/                генератор и проверки
```

Тексты тестов лежат врозь намеренно: браузер участника скачивает ровно тот тест,
который назвала его сессия. Иначе проходящий «до» получил бы заодно и тест «после».

**Источник истины — `spec/`.** Там правила тестирования, файл кейсов
(`вычитка_6_компаний.md` — все 6 кейсов с ключами и источниками), шаблон обёртки
судьи, профиль мини-формата, тексты отчёта от методолога и методология v8.
Тексты нигде не переписываются руками.

### Чего в этом репозитории нет

Репозиторий публичный, а GitHub Pages отдаёт из него всё подряд. Поэтому четыре
позиции сюда не коммитятся — иначе участник, заглянувший в репозиторий, получил
бы ответы:

```
spec/                         правила, тесты с ключами, обёртки судьи, профиль, методология
js/keys.js                    ключ расстановки (нужен только моковому режиму)
apps-script/keys.gs           он же для бэкенда
apps-script/judge_prompts.gs  промпты судьи целиком
```

Они лежат локально и в проекте Apps Script. Три последних восстанавливаются из
`spec/` одной командой:

```bash
python3 tools/собрать_тесты.py
```

**`spec/` не восстанавливается из этого репозитория — это отдельный источник
истины.** Он лежит в приватном `sedovnn/bazovy-test-spec`: та же папка
`spec/` внутри рабочей копии, но со своим git и своим адресом. Здесь она в
`.gitignore`, поэтому в публичный репозиторий не попадает.

```bash
git clone https://github.com/sedovnn/bazovy-test-spec.git spec
python3 tools/собрать_тесты.py
```

По образцу Искры: `imperfect-iskra-platform` публичный, `imperfect-iskra-backup`
приватный.

Тексты новостей (`data/*.json`) в репозитории есть — их браузер участника грузит
в любом случае, публичность репозитория тут ничего не добавляет. Ключей в них нет.

## Как поднять локально

```bash
python3 -m http.server 8788
```

Открыть `http://localhost:8788/host.html`, создать сессию, перейти по ссылке или
отсканировать QR.

**Моковый режим** — добавить к адресу `?mock=1`: данные лежат в `localStorage`
браузера, судья имитируется, в таблицу ничего не пишется и за судью не платится.
Этого хватает, чтобы прощёлкать весь путь. Работает и при заполненном `API_URL`.

Если репозиторий только что склонирован, моковый режим не заработает, пока нет
`js/keys.js`: положите `spec/` на место и прогоните генератор. На живом сайте это
не нужно — там считает Apps Script.

**Вернуться к своей карте:** после отправки на карте появляется ссылка вида
`index.html?r=<row_id>` — по ней результат откроется снова с любого устройства.
Она же запоминается в браузере: если ввести тот же код сессии, на экране входа
появится «открыть свою карту». Судья при этом не вызывается — карта собирается
из того, что уже записано в таблицу.

**Посмотреть карту, не проходя тест:** `index.html?demo=1` — открывает результат
сразу, на выдуманных ответах. Нужно и чтобы обсуждать вид карты, и чтобы показать
группе, что они получат в конце. Работает и на живом сайте:
[sedovnn.github.io/bazovy-test/index.html?demo=1](https://sedovnn.github.io/bazovy-test/index.html?demo=1)

Посмотреть, как выглядит карта, когда судья не ответил: `?mock=1&mockfail=1`.

## Apps Script — десять шагов

1. `script.google.com` → **Новый проект**, назвать «Базовый тест».
2. Загрузить в проект файлы из `apps-script/`: `Code.gs`, `judge.gs`, `scoring.gs`,
   `config.gs`, `keys.gs`, `judge_prompts.gs`, `обслуживание.gs` (порядок не важен).
3. Значок шестерёнки → **Настройки проекта** → включить «Показывать файл манифеста»,
   открыть `appsscript.json` и вставить содержимое одноимённого файла из `apps-script/`.
4. Там же, **Свойства скрипта** → добавить `ANTHROPIC_API_KEY` = ключ Anthropic.
   Консоль Anthropic при создании ключа предлагает identity federation вместо
   ключа — это для нагрузок в GCP, AWS, Azure и GitHub Actions, которые умеют
   выдавать короткоживущий OIDC-токен. Apps Script так не умеет, и ходим мы сырым
   HTTP без SDK, так что здесь — **«Continue with an API key»**.
5. По желанию добавить `MODEL` (по умолчанию `claude-sonnet-5` — как у судьи Искры).
6. Выбрать функцию `проверитьСудью`, нажать **Выполнить**, выдать разрешения,
   убедиться в логах, что пришёл JSON с четырьмя уровнями.
7. **Развернуть** → **Новое развёртывание** → тип **Веб-приложение**.
8. «Запуск от имени» — **от моего имени**; «Кто имеет доступ» — **Все**.
9. Скопировать URL веб-приложения (заканчивается на `/exec`).
10. Вставить его в `js/api.js`, строка `var API_URL = '';`, затем `git push` — Pages
    подхватит через минуту.

До этого шага сайт уже открывается, но на любое действие честно отвечает
«бэкенд не настроен» — это ожидаемое состояние, а не поломка.

Таблица с данными создаётся сама при первом обращении, её идентификатор
скрипт запишет в свойство `SHEET_ID`. Ключ API остаётся на стороне Apps Script и
в браузер не передаётся никогда.

**Правки в коде после публикации** подхватываются только новым развёртыванием.
Веб-приложение отдаёт зафиксированную версию, а не то, что в редакторе, — это
ловушка, на которой легко потерять полчаса: код в редакторе уже новый, а участники
получают старый. Через интерфейс: **Развернуть → Управление развёртываниями →
карандаш → Версия: новая**. Через clasp:

```bash
cd apps-script
clasp push --force
clasp version "что поменяли"
clasp deployments                      # взять id нужного развёртывания
clasp redeploy <id> -V <номер версии> -d "что поменяли"
```

Для clasp нужен `apps-script/.clasp.json` с `scriptId` вашего проекта — он не
коммитится, заводится руками по образцу из `clasp clone`.

## Этапы и выбор кейса

| Этап | id | Какой кейс |
|---|---|---|
| До потока | `before` | любой из шести, выбирает ведущий |
| После потока | `after` | любой, кроме того, что был у группы на «до» |
| Базовый тест | `single` | любой, выбирает ведущий |

Правило «один кейс дважды не даётся» проверяет бэкенд при создании сессии: на «после» нельзя взять кейс, который у группы с тем же названием был на «до», и наоборот. Сессии, заведённые на прежних тестах v1.x/v2.x, больше не открываются: участник видит просьбу попросить у ведущего новую. Прежние результаты открываются по ссылке как раньше — сохранёнными значениями.

**Сравнение «до/после»** делается по названию группы. Ведущий заводит две сессии с одинаковым названием и разными этапами; когда в обеих есть прохождения, внизу экрана ведущего появляются две карточки рядом, по одной общей шкале.

**Разбор комментариев.** Внизу экрана ведущего — «Комментарии группы»: свои комментарии участников по каждой из 4 способностей, сверху сильнее, с уровнем или «уточняется». Нажатие открывает комментарий на весь экран — только текст и навык, без имени и уровня. Помечен самый короткий из сильных. В именной сессии вывода нет.

### Как добавить кейс

1. Дописать кейс в `spec/вычитка_6_компаний.md` по образцу остальных: `# N. Компания`, `## Новость — Компания · месяц год`, абзацы, шесть `## Ветка комментариев N` (реплика, 4 комментария строкой `- …` от слабого к сильному), три `> **Ваш комментарий N.**` на своих местах. В комментарии 1 цель пишется как «цель — …. Что вы» — генератор берёт её для судьи. Сейчас генератор ждёт ровно 6 кейсов — число правится в `parse_cases`.
2. `python3 tools/собрать_тесты.py` — появится `data/case_<компания>.json`, кейс попадёт в список, промпт судьи соберётся из шаблона сам.
3. Загрузить `config.gs`, `keys.gs`, `judge_prompts.gs` в Apps Script и сделать новое развёртывание.

## Как обновлять новости

Правила требуют проверять факты выбранного кейса перед запуском и обновлять новости по запросу, а не по календарю.

```bash
# поправить кейс в spec/вычитка_6_компаний.md
python3 tools/собрать_тесты.py
python3 tools/сверить_тексты.py
python3 tools/сверить_промпты.py
python3 tools/штамп_версии.py
git add -A && git commit -m "…" && git push
```

Промпт судьи собирается из того же файла, поэтому новость и комментарии в нём обновляются сами. `tools/сверить_промпты.py` проверяет, что новость, все 24 комментария и 3 вопроса попали в промпт дословно.

Правка текста комментария меняет его метку, а вместе с ней и ключ: новые прохождения считаются верно, у прежних строк в таблице остаётся записанный балл.

`data/*.json` подписаны отпечатком содержимого, он лежит в `js/config.js` и подставляется в адрес файла. Поэтому после правки браузер заберёт новый текст сам.

## Когда пришла новая версия спеки

```bash
# положить новые md в spec/, прежние убрать — правил, профиля и методологии
# должно быть ровно по одному файлу
python3 tools/собрать_тесты.py
python3 tools/сверить_тексты.py
python3 tools/штамп_версии.py    # если тронут фронт
```

**`штамп_версии.py` — обязательный шаг перед пушем, если менялись css или js.**
Без него браузер держит прежние файлы до десяти минут, и участник на пилоте
получит предыдущую версию, ничего при этом не заметив. Скрипт дописывает
к ссылкам метку времени — этого хватает, чтобы браузер забрал новое.

Генератор перепишет `data/test_*.json`, `js/config.js`, `js/keys.js`,
`apps-script/keys.gs`, `apps-script/config.gs` и `apps-script/judge_prompts.gs`.
Эти файлы руками не правят — следующий прогон затрёт.

Если разметка спеки изменится, генератор упадёт с понятной ошибкой, а не соберёт
молча половину. Чинить в этом случае надо парсер в `tools/собрать_тесты.py`,
а не подкладывать данные вручную.

После генерации файлы `config.gs`, `keys.gs`, `judge_prompts.gs`, `scoring.gs`
нужно заново загрузить в проект Apps Script и сделать новое развёртывание.

### Приёмочный тест судьи

Раздел 7 правил: судья готов, когда на эталонных ответах с ручными уровнями
методолога не расходится с ними больше чем на 1, а спорные места уходят в ручную
проверку.

```bash
ANTHROPIC_API_KEY=sk-… node tools/приёмка_судьи.js
```

Скрипт ждёт файл `spec/тексты_для_Егора_*.md`; разметка описана в шапке самого
скрипта. **Файла пока нет, поэтому судья приёмку не проходил.** Скрипт написан
под прежнюю редакцию раздела 7 (4 типажа ответов и их порядок) и под выдачу без
ручной проверки — когда появится набор эталонов, его нужно будет поправить.

Один прогон стоит денег: по вызову судьи на каждый эталон. Запускается руками
после правки обёртки, профиля или методологии, не в цикле.

## Что решено за пределами спеки

Правила в одном месте не дописывают границу — прочитано так, правится в одном
месте (`js/scoring.js`, оно же `apps-script/scoring.gs`):

- **«Одна перестановка соседей» и «L5 не первым» пересекаются.** Перестановка
  первых двух реплик подходит под оба описания. Список читается сверху вниз:
  сначала 3, потом 2, потом 1, иначе 0 — то есть такой ответ получает 2.
- **Строка «в тесте выше, чем в своих ответах»** — расстановка в зоне «выбирает»,
  а уровень той же способности в свободном ответе 1 или 2. Пороги вынесены
  в константы `GAP_ZONE` и `GAP_MAX_LEVEL`.

Ещё четыре решения:

- **Общая шкала на карте** правилами не задана. Правила дают по навыку разные
  величины: у «Анализа контекста» расстановка по двум новостям (0–6), у
  остальных по одной (0–3) плюс уровень свободного ответа. На карте обе части
  нормируются в 0…1 и усредняются с равным весом. Это огрубление; и участник,
  и ведущий видят одну и ту же шкалу — иначе получились бы две системы оценки.
- **Комментарии в спеке идут без букв**, а ключ записан буквами `E → D → C → B`.
  Уровень выводится из места комментария в списке: первый «-» — уровень 2,
  четвёртый — уровень 5. L1 в комментариях не даётся — так заданы правила.
- **В публичный файл теста ни буквы, ни порядок спеки не уходят.** Каждый
  комментарий получает метку — шесть знаков от хеша его текста, — и комментарии
  в `data/*.json` пересортированы по метке. Связь «метка → уровень» лежит только
  в `js/keys.js` и `apps-script/keys.gs`, которых в публичном репозитории нет.
  Это не перестраховка: в прежней версии варианты лежали в `js/data.js` под
  буквами A–E и по возрастанию силы, то есть готовым ключом. Проверку на это
  делает `tools/сверить_тексты.py`.
- **Порог свободного ответа — 20 слов.** Правила задают объём предложениями
  (3–4 и 3), а поле считает слова. Порог живёт в `MIN_WORDS` в генераторе.
- **`temperature` у судьи не передаётся.** Спека просит 0, но Sonnet 5 отвечает
  на этот параметр ошибкой 400. Вместо него отключено рассуждение
  (`thinking: disabled`). Повторяемость не гарантирована и на деле: тот же текст
  может получить ±1 или переключиться между уровнем и «уточняется». Поэтому
  отчёт участнику назван приблизительным.

## Стиль

Токены скопированы из платформы «Искра» (`imp.v3/css/styles.css`, блок `:root`)
и её `DESIGN.md`. Скопированы, а не импортированы: проекты живут независимо.

Вермилион `#ff4800` — на входе и на карте результатов. Внутри теста вся семья
акцента голубая (`body.p-test`): в Искре это решение владельца от 07.08 —
внутри ассессмента вермилиона нет.

**Тёмной темы нет**, и это не упущение: её нет и в Искре. `DESIGN.md` прямо
запрещает тёмный фон, тёмное там ровно одно — плашка футера. Делать свою
означало бы сочинить палитру, которой в системе не существует.

Теней нет нигде: глубина — hairline-линии и бледные тинт-заливки. Радиус один
на весь проект — 8px.

## Расходы

Промпт судьи подаётся целиком: обёртка с кейсом, правило «что попробовать дальше»,
профиль мини-формата и методология v8 — около 146 тысяч знаков на каждый вызов,
свой на каждый кейс. Он статичный, поэтому помечен
`cache_control` и при потоке участников подряд считается по цене кэша. Один
вызов на участника, плюс вызов на каждый `rejudge`.

Сколько человек проходят одновременно: Apps Script держит 30 одновременных
выполнений на аккаунт — это жёсткий потолок. Реальное ограничение сверху —
лимит Anthropic на организацию; посмотреть его можно функцией `показатьЛимиты`
в `apps-script/обслуживание.gs`, она читает заголовки ответа API.
